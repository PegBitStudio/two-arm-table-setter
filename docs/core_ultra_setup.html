Core Ultra Setup Guide

How to set up and run the Two-Arm Table Setter on your brother's Intel Core Ultra laptop — so the final demo, the speed tests and the NPU results all come from the hardware Intel asked for. Plan for about 3–4 hours in total, most of it waiting while things run.

Steps
  1. Prepare the laptop
  2. Install the tools
  3. Get the project
  4. Set up Claude Code
  5. Quick check (10 min)
  6. Full test with the NPU
  7. Try the NPU for the AI parts
  8. Film the demo on Core Ultra
  9. Voice demo (optional)
  10. Update GitHub and the submission
  11. Clean up and hand it back
Why bother? Intel's brief says the final demo should run on a Core Ultra Series 2 or 3, and 20 of the 100 points are for OpenVINO optimisation on that hardware — including its NPU (a chip made for AI). Our own laptop is an older i7 with no NPU. This laptop closes that gap.

1Prepare the laptop

about 20 minutes

  1. Plug it in and keep it plugged in the whole time — speed results change a lot on battery.
  2. Confirm it's a Core Ultra: Settings → System → About → Processor should say "Intel Core Ultra". Series 2 models have a 200-number in the name (for example "Core Ultra 7 258V").
  3. Check the NPU is there: press Ctrl + Shift + Esc → Performance tab. You should see NPU in the list on the left (next to CPU, Memory, GPU).
  4. Update drivers: Settings → Windows Update → Check for updates, then Advanced options → Optional updates → install any Intel items (graphics, NPU). Restart if asked.
  5. Stop sleep: Settings → System → Power & battery → Screen and sleep → set "When plugged in, put my device to sleep after" to Never. Write down the old setting to restore later.
  6. Free space: you need about 10 GB free on drive C.
No NPU in Task Manager? The laptop may be older than Series 1, or the NPU driver is missing. Install the Intel NPU driver from intel.com ("Intel NPU driver Windows"). You can still continue — CPU and GPU results count too.

2Install the tools

about 15 minutes

Open PowerShell (Start → type powershell → Enter) and paste these one at a time:

winget install -e --id Python.Python.3.12
winget install -e --id Git.Git
winget install -e --id GitHub.cli

Then install the Claude desktop app from claude.ai/download (it includes Claude Code). Close and reopen PowerShell afterwards so it finds the new tools.

Check it worked: py -3.12 --version should print 3.12.x and git --version a version number.

3Get the project

about 20 minutes (mostly downloads)

Use C:\work — not Documents or Desktop, which OneDrive may try to upload (thousands of files).

mkdir C:\work
cd C:\work
git clone https://github.com/PegBitStudio/two-arm-table-setter.git
cd two-arm-table-setter
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install --upgrade pip
.venv\Scripts\python -m pip install -r requirements.txt

The last line downloads about 1.5 GB of libraries and takes 5–15 minutes. Then download the two AI models:

.venv\Scripts\python brain\get_model.py
.venv\Scripts\python bench\get_policy.py

That's the vision-language model (3.1 GB) and our trained robot policy (45 MB), stored in C:\Users\<name>\.models.

4Set up Claude Code

about 5 minutes

Open the Claude app, sign in with your own account, go to the Code tab and open the folder C:\work\two-arm-table-setter. Then paste this as your first message:

Say to Claude:

Read HANDOFF.md, then docs/core_ultra_setup.html. We're now on my brother's Intel Core Ultra laptop, set up in C:\work\two-arm-table-setter with the environment in .venv. Check the setup works, then help me run steps 5 to 10 of the guide. Keep answers short and simple.

Important: this is your brother's laptop. Sign out of Claude and GitHub before you hand it back (step 11). Never paste passwords or API keys into the chat.

5Quick check

about 10 minutes

.venv\Scripts\python bench\volunteer.py --quick

What you should see:

  • Step 1 lists CPU, GPU and NPU with their names
  • Speed numbers for the trained policy on each chip
  • "3/3 tables fully set"
  • "Done. Please send this file back" — it made volunteer_results.zip

Small black windows may flash — that's the simulator drawing camera pictures. If anything fails, ask Claude Code: "Step 5 failed — here's the error, fix it."

6Full test with the NPU

45–60 minutes — let it run

.venv\Scripts\python bench\volunteer.py

This measures every AI part on every chip (CPU, GPU, NPU), checks that speeding them up doesn't hurt the robot, and sets 10 hard random tables with the full robot. Results land in the volunteer_results folder and volunteer_results.zip.

PartWhat it tells the judges
ACT policy × CPU / GPU / NPU × FP32 / FP16 / INT8Speed on Core Ultra, and which chip suits a small robot model
Task check on each chip"Optimisation didn't break the robot" (Intel asks for this)
Qwen3-VL on each chip × 3 picture sizesSpeed of understanding a command, on the NPU too
10 hard tablesThe whole robot working on Core Ultra

7Try the NPU for the AI parts

about 15 minutes

Run the robot with the trained policy on the NPU, and the vision-language model on the NPU:

.venv\Scripts\python brain\run.py --seed 3 --policy --policy-device NPU "put the cup to the right of the plate"
.venv\Scripts\python brain\run.py --seed 3 --device NPU "set the table"

Look for "Trained ACT policy loaded (OpenVINO FP16, NPU)" and "AI model loaded on NPU". If the second one says CPU instead, this model doesn't run on the NPU yet — that's a fine, honest result; use --device GPU for it.

Say to Claude:

Look at volunteer_results/results.json. Which chip is fastest for the ACT policy and for Qwen3-VL on this laptop, and did any precision lose accuracy? Pick the best device for each part for the demo video.

8Film the demo on Core Ultra

about 1 hour — let it run

Replace GPU / CPU below with the best devices from step 7:

cd brain
..\.venv\Scripts\python make_video.py --seeds 10 --start 100 --hard --model --device GPU --out out\demo_10_tables.mp4
..\.venv\Scripts\python make_video.py --seeds 1 --start 3 --bump plate --out out\recovery.mp4
cd ..
.venv\Scripts\python submission\make_final_video.py --results volunteer_results\results.json

The finished video is submission\two_arm_table_setter_demo.mp4. Its cards now say "running on Intel Core Ultra …" and show the NPU numbers — the name is read from the laptop automatically.

9Voice demo (optional)

about 10 minutes

Your Speechmatics key is on your own PC only. To use it here, open PowerShell yourself (not through Claude) and run:

setx SPEECHMATICS_API_KEY "paste-your-key-here"

Close and reopen the Claude app so it sees the key, then:

.venv\Scripts\python brain\run.py --seed 5 --audio brain\test_command.wav

If test_command.wav is missing, ask Claude Code to make one with Windows speech, or record yourself saying "Please set the table" with the Sound Recorder app.

10Update GitHub and the submission

30–45 minutes

Safest: copy these to a USB stick or Google Drive and bring them to your own PC, then let Claude Code there update and upload everything:

  • volunteer_results.zip
  • submission\two_arm_table_setter_demo.mp4
Say to Claude (on your PC):

Here are the Core Ultra results (volunteer_results.zip) and the new demo video. Add the Core Ultra numbers to bench/RESULTS.md, the README, the slides and the demo page, put the new video on the demo page, and push to GitHub.

Or, from the Core Ultra laptop: run gh auth login, sign in to GitHub in the browser window, and ask Claude Code there to do the same. Remember to sign out in step 11.

11Clean up and hand it back

about 10 minutes

  • Copy your results off the laptop first (step 10)
  • Claude app → your profile → Log out
  • If you signed in to GitHub: gh auth logout
  • Remove the Speechmatics key (if you added it): run REG delete HKCU\Environment /F /V SPEECHMATICS_API_KEY
  • Delete C:\work\two-arm-table-setter and C:\Users\<name>\.models (about 5 GB)
  • Put the sleep setting back to what it was
  • Optional: uninstall Python 3.12, Git and GitHub CLI from Settings → Apps
